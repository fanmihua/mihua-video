# 封面

这里管封面本身：什么时候做、主画面放什么、标题、版面、出图。文中的「示例工程」是和这份 skill 一起给的完整工程（文件夹 `示例_幕后协作/工程/`），它的封面在 `cover/`。

## 什么时候做、做几张
- **4K 成片定了以后单独做一轮**，不和配音、录屏、场景并行，也不在出 4K 之前先做。为什么：跟着成片一起赶，封面容易一版版都不过关，白花时间。
- **每支 4 张：3:4（1242×1656）、4:3（1656×1242）× 白 / 黑**：`封面_3比4_白.png`、`封面_4比3_白.png`、`封面_3比4_黑.png`、`封面_4比3_黑.png`。用户说这支只要一种颜色时，照用户说的。
- **固定的只有 `cover/brand.css`**：尺寸；和视频一样的深灰舞台（径向渐变 + 虚焦方块 + 暗角 + 颗粒）；左上手写签名 + 右上头像；数黑 / 普惠字体；白版 `body.light`。**排版每支按这支的内容重新设计，不套模板。**

## 先对齐方向，再精做
- **先给 2–3 个方向**（文字 + 片中截图，或一张粗稿）：主画面用哪张、标题写什么、怎么排；用户选定一个再写 HTML 精做。只能上一张封面，一张要装下全部内容，不要一次精做好几张让用户挑。为什么：跳过这步直接精做，容易整版被退回、来回改很多轮。
- 先问用户有没有参考图。**用户给参考图：排版照学，内容全换成这支真实的**：参考图里的步骤名、假界面、假文件结构都不要，换成这支的真文件、真截图、片子里的步骤和每步的一句话。
- **用户已经有几版、各有优缺点时，就是「融合」**：先列出每版用户说的优点（要保住，不是可选项）和缺点，直接出一张融合粗稿，不另起新方向。为什么：另起的新方向往往会丢掉用户喜欢的那部分。

## 主画面
- **放结果**（这条最优先）：做出来的东西、改好的界面、一眼看得出差别的那组画面。不放要想一下才懂的比喻。为什么：看封面的人不会停下来想比喻，结果一眼就看得懂。
- **优先用片子里做好的主线图**：这支专门设计的流程图、拆解图（比如一张流程图：方框、箭头、每步下面挂着它交出去的东西），是片子里设计感最强、观众点进去会看到的画面，直接放大重排。不另外拼截图做「改前 / 改后」数值对比，那样没有设计感。
- **一定要有这支的真实画面**：剖面图、真组件、真截图、真文件摘录。钩子数字（比如「0 行」）做成一张卡片叠在画面旁边，不能拿大数字、大字代替画面，不然封面上只剩文字。
- 要表达「不一样」时，选差别一眼看得出的那组：几乎一样的几张放在一起，看的人只会觉得它们是一样的。
- **寸土寸金**：同一种界面不放两遍（两排几乎一样的控件条就是重复）。
- **插画只当配角**，不当主画面。用到插画时，这些照样用：
  - 要吸引人，不只是把几个元素摆好：这支最勾人的看点画进画面（比如讲省钱，就加一个存钱罐，放主角脚边、一起站在光里）；主角有表情和动作（抬眼看标题、张嘴笑）；画面往标题那边有动势（几样小东西往标题方向蹦，带速度线，问号旁三笔手绘「蹦」线）。
  - 拿片子里代码画的插画：从母版（示例工程是 `src/partials/set/master.html`）把要的分组复制进封面页，id 换前缀（如 `cv-`），母版和场景文件不动。深色舞台上给主角铺一圈亮的地面（聚光灯落地的光圈），浅灰影子改成半透明黑，不然会变成一块块亮斑。左右翻过来的道具，眼睛改成看向主角；被画面切掉的道具，认得出它的那部分（比如场记板的合页、脸）要留在画里。边角道具调暗（不透明度约 0.8），主角才是焦点。

## 标题
- 封面标题短，十个字上下；自媒体写具体的东西 + 痛点或反差。细节、方法放进片子里，不往封面上挤。
- **要能单独看懂**：没看过前几期的人，只看封面标题也知道这支讲什么——直接写出主角和它做的事，不用「一个数」这种看过片才知道是什么的说法。
- **标题的地方不让**：主标题保持大字号，别的元素放不下就缩别的、挪别的，不为了放钩子把标题压小；标题在上方，不往下压。参考字号：3:4 两行约 108 / 168px、4:3 约 86 / 142px；字更大的做法见下一条。
- **字要比画大**：标题和小标签整体放大、配图缩小一点。要挪位置时先问清挪的是文字还是插画，别一起动。示例工程的封面定稿：3:4 标题两行 216px、胶带字 58px；4:3 两行 200px、胶带字 54px；主角和道具缩小约 13%。胶带上沿离签名那一行留 60px 以上，不贴着顶。
- 主标题数黑、白色，一眼能读；关键词可以加一笔手写下划线；副标题里有数字就放大。
- **副标题写清谁做什么**：「人说感觉，AI 翻译成规则」比「从感觉到规则」准；少了主语，表达就不准确。
- **标题上方可以贴一小条装饰**：片子里同款的贴纸 / 胶带（白底黑字、轻微歪斜、同一套手绘抖动），四五个字（如「幕后全流程」）。它是标签，不是副标题。
- `script.md` › 6 里不对外的内容，封面上也不出现。

## 版面
- **最多三块**：钩子卡片、主画面、标题 + 副标题。封面在列表里显示得小，底部一排深色小缩略图只有指甲盖大，看不清，只会显得密，去掉（例外：白底、够大、差别一眼看得出的一排可以留）。只放这支的核心（问题 + 主角画面），不用把每章都塞进去。
- **字要少**：不要角落小字、英文小标、二级说明、前缀、标题下面的灰色副句（「选题 · 口播 · …」这种一行也不要）；剖面图平面里的小字也去掉。字一多就显得信息太密集。
- **上下要匀**：上半不能空、下半挤。出图前跑 `node cover/measure.mjs`，看每块之间的空和底边留空。
- 箭头、引线按元素的真实位置算（`cover/cover.js` 的 `coverArrow`、`coverCorners`），箭头头部沿曲线末端的方向；手摆的 SVG 箭头一眼就看得出歪。
- **连线进卡片要水平**：弯线要在进卡片前拉平（控制点离终点 ≥ 90px），箭头方向取线最后一小段的方向；空间不够就改成「主干 + 分支」（一根竖主干，几条水平分支，两头圆角），箭头全水平。
- 一排卡片的投影加在外层容器上（`filter: drop-shadow`）；每张卡单独加大投影，后一张的影子会压到前一张的右边。
- **横竖两版内容一字不差，摆法按画布重排**：元素可以换位置（竖版卡片放左上、编号线斜着往右上走；横版高度不够，面板铺满上半，卡片挪到右下和标题并排；示例工程的插画封面横版：主角和光束放右边，标题两行靠左，道具围在右下）。例外：横版放不下，先删最次要的一块（比如横版删掉底部一排步骤，竖版保留），不要每块都缩小。

## 出图
- 在 `cover/` 写 `cover_34.html`、`cover_43.html`。同一个页面写两套颜色变量：白版 `body.light`（浅底、签名反成黑字、去掉虚焦方块和暗角），黑版换 class 和 `<meta name="out">`。真实截图卡片两版都是白的。
- `node cover/measure.mjs` 量上下松紧 → `node cover/render.mjs --out ../成片`（2 倍：2484×3312 / 3312×2484）。页面最后用 `coverDone(…)` 收尾，出图工具等它摆完才截。
- 粗稿出到临时目录（`--out` 指到别处），定稿才写进 `成片/`。
- `cover/` 根目录只放定稿的两页：`render.mjs` 不带页面参数时，会把根目录里所有带 `<meta name="out">` 的页面都渲出来，旧版会盖掉新版。之前的版本挪进 `cover/<版本名>/`，改好相对路径（`../brand.css`、`../../assets/`、`../cover.js`）和 `<meta name="out">` 的文件名，只留档。

## 例子（只看做到什么程度，不复制排版）
- 示例工程的 `cover/`（`cover_34.html`、`cover_43.html`）：片场插画当主画面，聚光灯下的主角 + 道具，标题上方贴「幕后全流程」胶带，大标题「如何用 AI 做视频？」。插画的处理（光圈、影子、道具调暗、胶带、横竖两版的摆法）可以看；它的主画面是比喻插画、标题是话题名，选主画面和写标题照上面「主画面」「标题」两节，不照它。
