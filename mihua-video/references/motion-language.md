# 动效语言：画面怎么设计、镜头怎么走

品牌层管「长什么样」，这份文件管「怎么动、画面上放什么」。它是一套**词汇和规则**，不是成品场景。每支视频都从自己的口播和素材出发重新组合；两支视频的镜头顺序、主角素材、节奏应该不一样，但看起来是同一个人做的。

文中的「示例工程」是和这份 skill 一起给的完整工程（文件夹 `示例_幕后协作/工程/`）：每章一个场景 `src/scenes/act*.html`，代码画的插画在 `src/partials/set/`，场景层的卡片版式和小工具在 `src/partials/kit.css`、`src/partials/kit.js`，配置在 `video.config.json`，口播时间轴在 `timing/film.json`。想看某个做法具体怎么写，就去那里找；只学做法，不照搬画面。

## 1. 设计原则

1. **真实画面是主角，文字是标注。** 画面 70–90% 是真实的录屏 / 截图 / 代码，字只做「这是什么」的小标注；一屏一个信息点，其余交给口播和字幕。大字只在极少数地方当钩子，永远不当口号。
2. **口播提到什么，画面就放真的那个**：提到大纲就放大纲，提到素材、工程文件夹、分镜表、静帧、样片就放真的那个文件，提到参考视频就放参考视频（标出处，见 `materials.md` › 别人的作品），提到旧版就放旧版截图，提到某个音效就把那个音效放出来。旧版本删之前先问用户要不要留作素材。
3. **一镜到底，要 AE 剪辑感，不要 PPT 式一页页翻。** 一章是一块大画布，镜头在上面推、移、甩过去；章节之间用镜头运动衔接（甩、钻入、拉远），不用淡入淡出硬切。
4. **跟着口播走。** 每个镜头动作都锚在一句口播上（`C.<name>`）：口播说到哪个东西，镜头就在那一刻推到它、框出它、标注它。没有口播对应的动作就删掉。
5. **一个画面只有一个焦点**：几样东西同时变化，眼睛跟不过来。比较多个对象时，把要比的那一块单独抽出来（只看标签栏、只看输入框），一个一个出现，当前的亮、其他压暗，全部讲完才拉远看全表。
6. **克制，不要促销感。** 缓入缓出（expo / power3），不弹跳、不闪、不震；不要口号大字、闪白、放射线、贴纸砸下。高潮靠镜头推近 + 音乐抬起。
7. **深灰极简。** 视频里只有黑白灰，彩色只来自真实截图和录屏；不加装饰（小英文、彩色光点、密集圆点、重剪纸）；不用彩色色带（只在封面的另一种版式里用，见 `cover.md` 末尾）。讲解类画面只学教学课件的**讲解方法**（拆开看、尺寸线「画」出来、编号、流程用方框加箭头），**不用课件的白纸外观**。
8. **证据原样。** 别人的反馈、作品结果、聊天截图原样摆放，不推镜头、不加框、不加特效——真实感比动感重要（写法见 3.8）。

## 2. 从口播到分镜的方法

拿到 `timing/film.json` 后，逐章做这张表，给用户看（分镜是用户的关口，每支都要过）：

| 章 | 口播节点（C 名） | 主角素材 | 镜头 | 标注 | 转出 |
|---|---|---|---|---|---|

做法：
- **先找每章的「证据」**：这一章要让观众相信什么？最能证明它的那张真实画面就是主角。某一句想不到怎么表现，翻示例工程的 `src/scenes/act*.html`，看同类的句子画面是怎么做的。
- **每个知识点都变成画面上的变化**：拆层、叠合、量出数值、改前改后，不只是摆一张截图。
- **把口播里的名词对上画面里的位置**：口播说「组件」，画面上哪一块是组件？镜头就推到那里，outline 框住，note 标注。
- **每章 1 个主镜头动作 + 若干小动作**：主镜头是这一章最大的动（推近、甩过去、分层展开），小动作是框、标注、换图。
- **数一下动作密度**：大约每 2–4 秒一个有意义的变化；超过 5 秒没变化就加一个缓慢的 `cam.breathe(tl, wx, wy, s, from, to)`（传入镜头当前停留的点和倍数）；1 秒内多于 2 个动作就太乱。
- **画面不要空着等下一句**：甩镜头到新位置以后，那句口播要讲的东西要马上在画面上（真东西提前进来、名字先排出来再一项项亮），不要出现两三秒只有底色、或只有一个小标签的空屏。口播是过渡句（「这里我想多说一句」「然后是音效」）时，先停在上一个画面上，说到下一件事再甩过去。自查时每 3 句截一张，空屏、半空屏挑出来。
- **换话题的停顿里画面也停一下**：回到全貌图、亮出这一步的小结，不要黑着等（停顿怎么写见 `audio.md` › 节奏）。
- **字幕安全区**：画面底部约 130px（舞台 y > 950）是字幕区。标注、框选、重要文字不要放进去——也要算上镜头推近后它们会被推到哪里。顶部约 110px 是签名、导航和头像，同样留空。

## 3. 镜头词汇

所有函数在 `src/common.js`，组件在 `src/theme.css`。下面的「示例」只是写法，位置和时间要按你的内容算。

### 3.1 推近 / 拉远（`cam.focus` / `cam.home`）
**用于**：口播说到画面里某个具体东西时。推近倍数 1.3–1.8（4K 素材在 1.8 倍内仍清晰）。
```js
const cam = hfCam("#x-w");                         // #x-w 是这一章的整块画布
cam.focus(tl, 1378, 476, 1.7, C.drift - 0.3, 1.0);  // 把世界坐标 (1378,476) 推到画面中心
cam.home(tl, C.next - 0.6, 0.6);
```

### 3.2 甩镜头（`hfWhip`）
**用于**：同一章里从一个素材跳到下一个素材（并排摆在画布上，相距约 1500–2600px）。自带运动模糊。
```html
<svg width="0" height="0" style="position:absolute"><filter id="x-mbh" x="-30%" y="-5%" width="160%" height="110%"><feGaussianBlur id="x-mbhg" stdDeviation="0 0" /></filter></svg>
```
```js
hfWhip(tl, cam, "#x-w", document.getElementById("x-mbhg"), 3560, 540, 1, C.fac - 0.45, "x");   // 纵向甩用 "y" + 纵向放宽的 filter
```
提前 0.4–0.5 秒起甩，落点正好在口播说出那个名词时。不配音效（音效只放章节之间）。

### 3.3 窗口入场（`hfArrive`）
**用于**：一个新的真实界面登场。从纵深飞入 + 对焦。
```js
hfArrive(tl, "#x-win", C.qa - 0.2, { z: -2200, rx: 18, rx2: 4 });
```

### 3.4 剪出浮起（`hfLift` + `.cutout`）
**用于**：录屏 / 截图里有一小块最关键（一条聊天、一个标题、一张卡片），把它「剪」出来放大到前景，背后窗口压暗。素材从原始 4K 帧里裁（`ffmpeg -ss t -frames:v 1 -vf crop=…`），不是重画。
```js
hfLift(tl, "#x-cut", "#x-win", C.ask + 0.3, { x: -537, y: 1, scale: 0.75 });  // from = 它在截图里的原位置
```

### 3.4b 改前 / 改后（讲「改好以后」「改了一个数，界面跟着变」）
- **讲「改好以后」就放改好的同一个东西**：改前、改后成对出现（改前划掉、变暗，改后放大），不换成一个不相干的画面。
- **改了一个数，要把「变」的那一下放出来**：只放改完的样子，观众看不到变化。做法：
  - 素材：同一画面的改前、改后两张真截图（同一视口、同一位置）；要放大 2 倍以上就补拍 4 倍截图（录屏工具 `deviceScaleFactor: 4`，改后那张用 `edits` 改文件、截完自动还原）。
  - 把变化的那一小块剪出来放大（差别只有几像素时，整页推近看不出来）：两张裁同一块，叠在一个 `.cutout` 里（改后那张先透明），从它在页面里的原位置 `fromTo` 放大浮出来。压暗父层不要用 hfLift：父层滤镜从 none 补间会先闪黑，用起止写全的 `brightness() blur()`（见 `pitfalls.md`）。
  - 就地直接切（透明度 ≤0.06 秒），不淡入淡出（会叠影）；**只切一次，切完停住**：同一扇窗「改前 → 改后 → 改前 → 改后」来回切，看着一闪一闪，一会儿像半透明、一会儿像实色。要观众看清差别，靠并排的两样（改前、改后各一扇窗，左右摆）或前后两个画面，不靠同一扇窗来回切。要切的那扇窗在切之前别压暗挂着：压暗的半透明 → 亮起 → 切换，会多出一下「闪」；还没讲到的结果先不出现，讲到时直接以结果出现。
  - 旁边两条尺寸线并排：虚线「改前 + 数值」量改前那张，实线「改后 + 数值」量改后那张，改后出现时画出来。
  - 讲完缩回页面原位置，镜头拉远，每处各标一个改后的数。
  - 真实操作里难看的中间过程（保存后整页刷新回首页）可以不放，用改前那一帧盖住，但「变」本身必须看得见。

### 3.5 框选 + 标注（`.outline` + `hfOutline`，`.note` + `hfNote`）
**用于**：几乎每个镜头落点。outline 放在窗口**内部**（跟着镜头一起缩放），note 放在旁边空白处，「圆点 + 引线 + 深色小标签」，标签写「这是什么 · 补充一句」。
```html
<div class="outline" id="x-box" style="left:871px; top:250px; width:495px; height:52px"></div>
<div class="note" id="x-n1" style="left:330px; top:930px"><span class="dot"></span><span class="ln"></span><span class="t">规范原文<small>只写了文字说明</small></span></div>
```
```js
hfOutline(tl, "#x-box", C.drift + 0.2);
hfNote(tl, "#x-n1", C.drift + 0.9, 3.0);   // 3 秒后淡出（不传则一直留着）
```
- **框要对准真实内容，位置量出来，不估**：图层 PNG 按 alpha 找内容边界；真实截图、网页里的某一块从截图 / 页面里量（录屏工具记下元素位置）；导航这类外壳上的东西，先在构建出来的页面里量实际位置。渲染前把每个框那一刻截图放大看。
- **框住一张卡片、一行字时，框做成它的子元素**：`<div class="outline" style="left:-12px; top:-12px; right:-12px; bottom:-12px; border-radius: 卡片圆角+10px">` 放进卡片里面，四边等距，卡片多大框多大（示例工程 `src/partials/kit.css` 里的 `.outline.fit` 就是这种写法）。不要在外面另放一个手估坐标的框：卡片自带一圈描边，两圈一叠四边距离不一样，就显得歪、像错位。
- **框要和底下有反差，一眼看得见**：白色界面上放白框，看不出框选了什么。品牌层的框是一黑一白两圈。框在白色截图、浅色界面里面用 `.outline.dark`（黑圈为主）；白框 `.outline` 只放在深色舞台、深色标题栏上（框住整张卡片、地址栏）。几张小卡片并排时，框不能伸出卡片（内容比卡片长就裁到卡片里），不然会压到卡片下面的名字。拿不准就截那一刻放大看。
- **标注的圆点落在被标的东西上**：圆点落在目标（或它的边）上，引线朝空着的那一边伸出去，字在引线末端；字在目标右边用 `.note`，在左边用 `.note.l`（圆点在右端）。位置按目标的版面位置算（目标的 offsetLeft/Top 加到标注所在的那一层），不手估；不要出现字贴着目标、圆点飘在外面的反向标注。现成的小工具在示例工程的 `src/partials/kit.js`（`pin` / `pinAt`，用法写在文件开头的注释里）。

### 3.6 失焦对比（`hfRack`）
**用于**：一组并列素材里点名其中一个（多张卡片、多个文件、多条反馈）。
```js
hfRack(tl, "#x-p2", ["#x-p1", "#x-p3"], C.asset - 0.2);
```

### 3.7 真实代码 / 文档面板（`.code` + `tools/code_panels.py`）
**用于**：讲「规范、组件、配置、Skill 文件」时，直接给看项目里的真实文件。高亮行 `.hl` 跟着口播逐条亮起，多个文件并排、甩镜头逐个看，最后拉远看全局。
```html
<div class="code" id="x-p3"><div class="tab"><b>badge.tsx</b><span>组件实现</span></div><!--@@INCLUDE:src/partials/badge-tsx.html@@--><div class="hl" id="x-h3" style="top:180.25px; height:209.25px"></div></div>
```
```js
tl.fromTo("#x-h3", { scaleX: 0 }, { scaleX: 1, duration: 0.5, ease: "power3.out" }, C.asset + 0.75);
```
**代码是给不写代码的人（比如设计师）看的**：真实代码一个字不改，也不往里插注释；标签栏左边写一句大白话标题（白色大字），文件名退到右边灰色小字（`.tab.say`）；只亮关键的 1–2 行，其余压暗（`hfFocus(tl, 面板, [要亮的行], 时间)`）；亮的那行旁边再用标注说一句人话，标题和标注不说同一句话。
文档（Markdown 讲义）用 `.code.doc` + `.page`，要强调的句子包 `<mark>`，用 `--m` 从 0 到 1 画底色。

### 3.8 原样摆放（`hfReveal`）
**用于**：观众反馈、作品截图、群聊原话——证据类素材。依次浮现后**不再动**，用明暗分组（当前一组亮、其他组 30% 透明度）。
```js
hfReveal(tl, "#x-f1", C.fb - 0.2 + i * 0.16);
tl.to(otherGroup, { opacity: 0.3, duration: 0.5 }, C.made - 0.15);
```

### 3.9 文字（`hfChars` + `hfTextIn` / `hfTextOut`）
**用于**：极少数需要一个词撑画面的地方（钩子、章节卡、结尾标题）。字逐个从模糊里升起。字号用 `.h-l` / `.h-m`，一屏不超过一行大字。不做口号。

### 3.10 讲概念、讲流程的画面
- **讲概念不要只摆文字卡**：只有字的卡片没有设计感。有真东西的地方放真东西（评论截图、导航、真文件）；纯概念的地方画成这期自己的插画小场景（比如片场道具：场记板上的片名条、导演椅 = 人、摄影机 = AI、中间一本 Skill 手册；示例工程的 `src/partials/set/` 就是这样一套用代码画的插画）。连接、编号、流向用细线（白芯 + 深色描边的虚线，两种底上都看得见）；字只做短标签，贴在画面里的胶带、卡片上。线条画之前整条藏起来（圆角线头会先冒出一个点，见 `pitfalls.md`）。
- **文字卡片统一版式**：一支片子里讲概念的卡片用同一套网格（左右各留 160px，两栏 1000 + 40 + 560 或 520 + 40 + 1040）；卡片里固定三级——小标签（灰色小字）→ 主句（数黑大字）→ 例子（普惠中字），间距固定；证据截图放进它支撑的那一栏，不在旁边飘着；不要几行字、一个括号、一列截图零散摆。写成这期自己的 `src/partials/kit.css`（场景层，不是品牌层）；示例工程的 `src/partials/kit.css` 是现成的一份（`.kp` 卡片里 `.lab` / `.ttl` / `.eg` 三级）。
- **插画线条不做抖动动画**：线条一直抖，反倒影响阅读。手绘质感用静态的 SVG 滤镜（线条不规则、细颗粒），滤镜参数不随时间变；不做每几帧换一次 seed 的「线条活着」效果。
- **卡片变白时，小字跟着变黑**：卡片里的编号、小字用 `currentColor` + 透明度，不写死白色；凡是「变白高亮」的地方都截图看字还在不在。
- **流程、步骤类画面给足细节**：每一步放真实文件，字号放大，用白底黑字的「荧光笔」划重点，旁边标注说一句人话；分镜就做成真的表格。内容不怕被看，但不对外的内容照样不放（`script.md` › 6）。

### 3.11 放以前成片的窗口，裁掉它自带的字幕
按这套流程做出来的成片都烧了字幕（画面 89%–96% 高度）。缩成窗口放进新片子时，窗口 `.body` 里的画面按 16:9 贴顶、底下 12% 裁掉（窗口高 = 40 + 宽 × 9/16 × 0.88；写法见示例工程 `src/partials/kit.css` 的 `.nocap`）。为什么：两行字幕一叠，观众分不清哪句是现在在说的。

### 3.12 可选的「大动作」（一支视频最多用 1–2 次）
- **3D 分层展开**：一个界面倒成等轴测，按「底层 → 中层 → 顶层」拆开再合上（讲层次时）。`perspective` 容器 + `preserve-3d`，各层 `z` 拉开。层数少一点；互相挡住的拆开平铺，或把被挡的内容挪到不挡的位置。
- **演示动效要看得出来**：讲「拆开、堆叠」就真的在 3D 里沿 z 拉开再合上，每个动作下面标名字；平面上斜着挪一下等于没演示。时间不够就在稿子里加停顿给演示留时间。
- **3D 轮播**：3–5 张卡片排在弧面上，讲到哪张转到正前（并列介绍几项时）。卡片间角度 ≥ 50°、半径 ≥ 1250px，否则侧卡会穿到正前方卡片前面。
- **钻入转场**：镜头推进一张卡片（缩放到 7 倍 + 模糊）进入下一章。
- **卡片墙**：几十张真实小卡片从倾斜平铺到正面，表达「数量多」。

## 4. 章节结构

- **开场（第一个 act）：自媒体开头 3 秒给结果**（口播怎么写见 `script.md` › 2；教程的开头照 `script.md` › 0）：
  - 第 0 秒就是这期的结果画面（全片最有冲击力的那张真实画面，全屏，角落一个 note 说明是什么）；签名在第一句口播开口时写出（外壳自动做）。
  - 钩子必须是**这一期自己的画面**（这期的主角画面、剖面图或封面同款画面），不沿用上一期的开场动画，观众会以为发错了视频。要提上一期，放在钩子之后，缩成窗口，标明「上一期」。
  - 画面上不放招呼语文字；导航在钩子之后出现（`navFrom`）；不配「镜头依次扫过每章」的目录镜头。
  - 钩子可以做成 3D 拆解图：横向一条轴 + 竖着的画面薄片，做出 X/Y/Z 纵深——最前面是完整的一帧，后面一张张是它的各层（白纸、反相），轴上每层一个点、一条虚线落到薄片上、一个编号名字。透明度放在 3D 容器的外层，放在 preserve-3d 那层会把 3D 压平。
- **每章开头**：导航自动下划到这一章（外壳根据 act 开始时间做）。镜头从上一章甩 / 落进来。
- **章节之间**：上一章结尾 `y: -1300` 往上甩出 + 纵向运动模糊，下一章从下面落进来；或者整块虚化淡出、下一章从虚化里对焦出来。两种交替用，不要全片一种。
- **结尾**：最后一句口播时，本期主角素材收成一排退到背后，`.endcard` 出现（标题 + 细线 + 署名一行），最后 0.8 秒压黑。`navUntil` 设成最后一句。画面里自己就有文字的尾幕用 config 的 `noCaptions` 关掉底部字幕。`navFrom`、`navUntil`、`noCaptions` 和口播节点别名 `aliases` 的写法，照示例工程的 `video.config.json`。

## 5. 禁止清单

| 不要 | 为什么 / 换成 |
|---|---|
| 口号大字（「最近更新了！」「跑通了！」） | 像促销 → 字幕关键词反白 + 镜头推近证据 |
| 闪白、放射线、镜头震动、贴纸 / 印章砸下 | 像广告 → 镜头 + 音乐抬起 |
| 用代码重画界面、聊天气泡、手机页面 | 不真实 → 真实截图 / 录屏 + 剪出浮起（AI 工具里的对话例外：要用户手动操作才能录的，用代码画简化界面模拟，见 `materials.md` › 录屏） |
| 把旧视频的场景整个复制改字 | 每支都一样 → 按本片口播重新设计 |
| 每次镜头横移都配 whoosh | 吵、盖过人声 → 音效只放章节之间 |
| 推镜头推到 2 倍以上 | 素材会糊 → ≤1.8 倍，或先裁更高清的局部 |
| 观众反馈推镜头、加框、加特效 | 显得刻意 → 原样摆放，明暗分组 |
| 写死秒数 | 换口播就全错 → 一律从 `C` 算 |

## 6. 场景骨架

每个 act 一个文件 `src/scenes/<actId>.html`。只有结构是固定的，里面的内容全是这一章自己的。只用 `src/common.js` 的动作（hfCam / hfWhip / hfArrive / hfLift / hfNote / hfOutline / hfRack / hfReveal / hfTextIn…）和 theme.css 的组件；场景自己的布局写在场景内 `<style>`。填满内容的完整场景，看示例工程的 `src/scenes/act*.html`。

```html
<!doctype html>
<html>
  <head><meta charset="UTF-8" /></head>
  <body>
    <template>
      <style>
        /*@THEME@*/
        /* 这一章的布局：id 一律以本章前缀开头（如 x-），避免和其他章冲突 */
        #x-root { position: absolute; inset: 0; color: var(--ink); font-family: "PuHui", sans-serif; }
        #x-w { position: absolute; inset: 0; transform-origin: 50% 50%; }   /* 整章画布，镜头作用在它上面 */
      </style>
      <div id="x-root" data-composition-id="actX" data-width="1920" data-height="1080" data-duration="@@C.end@@">
        <!-- 需要甩镜头时放 svg filter -->
        <div id="x-w">
          <!-- 真实素材：.win / .code / .cutout / video（data-start 用 @@C.xxx-0.6@@ 这种表达式，单位是本章内秒数） -->
        </div>
        <!-- 不跟镜头动的标注放在 #x-w 外面 -->
      </div>
      <script>
        //@COMMON_JS@
        (function () {
          const C = /*@CUES@*/;            // 本章口播节点：C.l1, C.l1e, …, C.<alias>, C.end
          const tl = gsap.timeline({ paused: true });
          const cam = hfCam("#x-w");
          // … 按分镜表逐句写动作，每个时间都从 C 算 …
          window.__timelines["actX"] = tl;   // 必须和 data-composition-id 一致
        })();
      </script>
    </template>
  </body>
</html>
```

视频元素：`<video src="assets/video/x.mp4" muted playsinline data-start="@@C.qa-0.6@@" data-duration="@@C.info-(C.qa-0.6)@@" data-media-start="0.2"></video>`，放在场景内即可（不要再套一层带 data-start 的容器）。窗口、卡片里的 `<video>` 宽高写死像素（或用 `.win .body > video`），不要只靠 `aspect-ratio`（原因见 `pitfalls.md`）。

## 7. 坐标和时间的算法

- 画布 1920×1080，渲染时整体放大 2 倍到 4K。素材按 4K 原图放，显示尺寸写 CSS 像素。
- `cam.focus(tl, wx, wy, s, …)`：把画布坐标 (wx, wy) 放到画面中心、缩放 s。窗口内元素的画布坐标 = 窗口 left/top + 标题栏 40 + 元素在 body 里的位置。
- 截图里某块区域的位置：原图像素 × (窗口显示宽 / 原图宽)。
- 代码面板高亮行：`top = 64 + (行号 − 起始行) × 23.25`，`height = 行数 × 23.25`。
- 时间：动作在口播名词出现前 0.2–0.5 秒开始，让镜头「到达」正好对上口播说出那个词。章节转场在下一章第一句前 0.4–0.5 秒开始。
